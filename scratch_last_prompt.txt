5. IDENTITY RESOLUTION ENGINE
==================================================

Upgrade the current matching architecture into a multi-level parcel identity engine.

Matching should be evaluated in a controlled sequence.

LEVEL 1:
Exact parcel identifier match

LEVEL 2:
Normalized parcel identifier match

LEVEL 3:
Strong source-specific identifier match

LEVEL 4:
Owner similarity

LEVEL 5:
Area similarity

LEVEL 6:
Coordinate proximity when coordinates are available

LEVEL 7:
Address similarity when appropriate

Create a transparent matching result.

Every match should explain WHY the records were matched.

Example:

MATCHED
- normalized parcel ID exact
- owner similarity 0.94
- area difference 2.1 sqm

or:

POTENTIAL MATCH
- owner similarity 0.88
- area similarity 0.97
- identifier unavailable

or:

UNMATCHED
- no reliable common identifier
- owner similarity below threshold

IMPORTANT:

Do NOT implement advanced geospatial processing here.

Simple coordinate-distance comparison is acceptable where already supported.

Advanced spatial matching belongs to PHASE D.

7. MATCH STATUS
==================================================

Every source-to-source/canonical relationship should be classified into states such as:

- MATCHED
- POTENTIAL_MATCH
- UNMATCHED
- CONFLICT

Keep the distinction clear:

MATCHED:

POTENTIAL_MATCH:
Evidence exists but requires review.

UNMATCHED:
No sufficiently reliable correspondence found.

CONFLICT:
Records likely refer to the same parcel but contain meaningful disagreement.

Do not confuse "unmatched" with "conflict".
